# Workspace Dependency Catalogs Design

## Goal

For generated Bun and pnpm monorepos, move shared dependency versions into package-manager catalogs so repeated dependencies stay in sync.

---

## Background

`packages/template-generator/src/post-process/catalogs.ts` already detects duplicate dependency versions and emits catalogs for Bun and pnpm, but the package path list is static and will miss new generated workspaces like `apps/tauri`, `packages/email`, `packages/i18n`, and `packages/observability`. This design improves catalog discovery to be fully dynamic.

---

## 1. Target Behavior

When `packageManager` is `bun` or `pnpm`:

1. Scan all generated workspace package manifests dynamically instead of using a hardcoded path list.
2. Find dependencies and devDependencies used by two or more packages with the same version.
3. Move those versions into:
   - Bun: root `package.json` `workspaces.catalog`
   - pnpm: root `pnpm-workspace.yaml` `catalog`
4. Replace dependency versions in package manifests with `catalog:`.
5. Never catalogue:
   - Workspace packages
   - Packages with conflicting versions
   - Package-manager specific protocols that are not semver-like

---

## 2. Risk and Constraints

- Preserve comments in pnpm YAML if possible; accept normalized YAML if tests are stable.
- Do not catalogue protocols like `workspace:*`, `file:`, `link:`, `portal:`, or already-present `catalog:`.

---

## 3. Implementation

1. Replace `PACKAGE_PATHS` in `post-process/catalogs.ts` with workspace glob discovery from the generated root package.
2. Include `apps/*`, `packages/*`, and any future generated workspace globs.
3. Keep the existing duplicate-version algorithm, but add guardrails for:
   - `workspace:*`
   - `file:`
   - `link:`
   - `portal:`
   - `catalog:` already present
4. Update pnpm generation to preserve comments if possible, or accept normalized YAML if tests are stable.
5. Add tests for both Bun and pnpm output.

---

## 4. Tests

- Bun generated stack has root `workspaces.catalog`.
- pnpm generated stack has `pnpm-workspace.yaml` `catalog`.
- Shared dependencies such as `typescript`, `zod`, or framework packages are replaced with `catalog:`.
- Single-use dependencies keep their direct versions.
- New packages generated by other plans are discovered automatically.
